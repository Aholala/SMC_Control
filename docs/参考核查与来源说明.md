## 2. 阅读公式前的最少约定

本节是为核查源码建立的记号表，不要求现在开始学习全部公式；正式教学仍按学习路线逐步介绍。

- 角度是转到的位置，记为 `θ`；角速度是角度随时间的变化率，记为 `ω`；角加速度是角速度的变化率。
- 目标角度记为 `θd`。角度误差记为 `e=θ−θd`，本轮三个位置控制实现都使用“测量减目标”。
- 字母上方一个点表示随时间的一次变化率，两个点表示二次变化率。因此 `ė=ω−θ̇d`。
- 控制输入 `u` 是算法交给执行端的数值。它可能是力矩、电流或协议命令；三者的单位和比例不能混用。
- 输入增益 `b` 是“单位输入能引起多少角加速度”的系数。理想对象可以写成 `θ̈=b·u`，不是直接指定某型号电机的真实模型。
- 滑模变量 `s` 是根据误差计算的标量；滑模面是满足 `s=0` 的状态集合。普通位置控制使用 `s=ė+c·e`。
- 趋近律是规定 `s` 应怎样随时间靠近零的规则；控制律是最终算出 `u` 的公式。这两个概念不同。
- 符号函数 `sign(x)` 在正数、零、负数时分别返回 `1、0、−1`。
- 饱和函数是把数值约束在一定范围内的函数；本文标准写法 `sat(x)` 在 `|x|≤1` 时返回 `x`，否则返回 `sign(x)`。
- 误差积分是误差随时间的累计。源码中用每次误差乘计算间隔，再累计近似计算。
- 误差死区是把一段小误差范围作特殊处理的规则；输出限幅是限制输出数值的大小。两者不是同一件事。

推导和适配时统一先声明角度单位 `Q`、输入单位 `U`，时间使用秒。`Q` 可以是弧度或度，但同一计算链必须一致。

| 量 | 普通位置控制中应有的单位或含义 |
| --- | --- |
| `θ、θd、e、error_eps` | `Q` |
| `ω、θ̇d、ė、s` | `Q/s` |
| `θ̈d` | `Q/s²` |
| `c/C、K` | `1/s`，此处限普通线性滑模面及对应线性趋近项 |
| 独立切换强度 `epsilon` | `Q/s²`，前提是它乘的是无量纲的符号或饱和函数 |
| `b` | `Q/(s²·U)` |
| `1/b` | `U·s²/Q` |
| `u、u_max` | `U`；具体是不是 A、N·m 或协议计数必须另行确认 |

饱和函数的输入必须经过尺度约定。若 `s` 有单位，应明确一个与 `s` 同单位的宽度 `phi`，使用 `sat(s/phi)`；不能认为源码裸写的阈值 `1` 在换单位后仍保持同样效果。

## 3. A：复旦 2025，普通位置滑模

### 3.1 实际计算与调用顺序

来源：`SMC_Controller/SMC/slidingmodec.cpp:6` 的 `SMC_Tick()`。

调用方式：构造实例 → 写入 `ref` → 每个计算周期提供角度与角速度 → 调用 `SMC_Tick()` → 使用成员 `u`。

README 指定角度为度，角速度为度每秒。示例对象为全局 `YawSMC`。源码核心顺序为：

1. `error=angle−ref`。
2. `ddref=(ref−refl)−dref`，再计算 `dref=ref−refl`。
3. 若位置误差进入死区，令 `u=0` 并立即返回。
4. `s=C·error+(ang_vel−dref)`。
5. `u=J·[ddref−C·(ang_vel−dref)−epsilon·Sat(s)−K·s]`。
6. 限制输出，最后才更新 `refl=ref`。

`C` 决定角度误差与误差变化率的组合；`K` 乘 `s`；`epsilon` 乘饱和函数；`error_eps` 为角度死区；`u_max` 为输出绝对值上限。示例参数是原作者工程数值，不作为本库默认参数。

### 3.2 值得参考

- 核心代码短，适合把误差、滑模变量、控制输出逐项对应。
- 明确提供角度与角速度两个反馈量，适合入门位置控制。
- 附件展示先讨论面内运动、再设计到达过程的思路。
- 输出限幅和符号函数、饱和函数便于建立最小实验。

### 3.3 已发现的问题与需要核对的内容

**A01：附件与代码中 `J` 的位置相反。** 附件第一页把模型写成 `ω̇=J·u`，第二页据此给出的输出是某个括号量除以 `J`。实现文件第 22 行却把相应括号乘以 `J`。如果沿用附件的模型，代码中的系数应解释为附件系数的倒数。不能一边称两者为同一个惯量，一边直接复制同一个数值。

**A02：目标变化量缺少时间换算。** `ref−refl` 是角度差，不是度每秒；再次相减也不是度每秒平方。实现把它们直接与角速度或相应项相加，作者 README 也承认这里没有严格统一单位。对运动目标不能直接认为其等价于理论公式。

**A03：构造函数没有初始化动态历史量。** `dref、ddref、refl、u` 等没有在构造函数中全部赋初值。原全局示例对象会先得到静态零初始化，但普通局部对象不能依赖这个条件。即便全零，初始目标不为零时也需要规定第一拍怎样建立历史。

**A04：死区提前返回会跳过 `refl` 更新。** 下一次离开死区时，目标变化量可能跨越多个调用周期。只检查位置误差还可能在高速经过目标时撤去控制输出，是否采用此规则必须单独验证。

**A05：输出和模型参数的物理映射不完整。** README 建议把 `u` 交给电流发送函数，但没有建立机械惯量、转矩常数、角度单位与协议数值之间的完整换算关系。输出 `25000` 也不能直接解释成安培。

**A06：不满足独立算法库边界。** 头文件依赖 STM32 硬件头文件，实现含具体云台全局对象；没有参数合法性检查与显式失败反馈。这些都需要在独立库中重新处理。

附件来源：`SMC_Controller/附件/滑模控制器设计.pdf`，两页均已提取文字并查看渲染图核对公式。

## 4. B：川大火锅，多种位置与速度控制

### 4.1 实际实现与调用顺序

来源：`Sliding/code/Sliding.cpp` 的 `ErrorUpdate()` 与 `SmcCalculate()`。

调用方式：创建实例 → `Init()` → 选择匹配的 `SetParam()` → 每周期调用对应 `ErrorUpdate()` → `SmcCalculate()` → 使用返回值或 `Out()`。其中返回值与 `Out()` 在某些路径并不一致，见 B02。

时间间隔在头文件中固定为 `SAMPLE_PERIOD=0.002`，即 2 ms。位置目标的一次、二次变化率按该周期差分；误差积分也按该周期累计。实际调用间隔变化时，公式不再与真实时间一致。

推导文档从 `力矩=惯量×角加速度`、`力矩=转矩常数×电流` 出发，把转矩常数并入名为 `J` 的系数。因此其 `J` 不是可直接从机械模型抄来的纯物理惯量，角度与输出命令的换算也会进一步影响该系数。

以下仅用于核查分支，不作为入门时一次性讲授的算法清单：

| 源码标识及位置 | 按实际公式描述 | 必须辨析的地方 |
| --- | --- | --- |
| `EXPONENT`，第 136 行起 | `s=c·e+ė`；输出为 `J·(−c·ė−K·s−epsilon·Sat(s))` | 目标二次变化率项被注释，不是完整运动目标公式 |
| `POWER`，第 150 行起 | 同样的 `s`；输出含 `−K·s−K·|s|^epsilon·Sat(s)` | 同时有线性项和幂次项；同一个 `epsilon` 还参与 Sat 的尺度，不能只照名称解释 |
| `VELSMC`，第 189 行起 | 此处误差改成速度测量减目标速度；`s=速度误差+c·速度误差积分` | 控制对象、误差单位和位置分支不同；保留目标速度的一次变化率项 |
| `EISMC`，第 195 行起 | `s=c1·e+ė+c2·误差积分`；输出增加 `−c2·e` 项 | 应从公式研究持续外力下的误差，不把它当成独立重力补偿器 |
| `TFSMC`，第 164 行起 | 用带正负号的误差幂代替线性误差项 | 详见下一节的终端形式核查；名称不能代替公式分类 |

上述幂次表示将数值提升到指定指数；负误差在终端分支里先取绝对值求幂，再恢复符号。

参数进一步按使用位置区分，不能给跨分支复用的名称强行指定一种单位：

| 参数 | 实际含义与单位核查 |
| --- | --- |
| `J` | 代码乘在整个括号外的比例；在文档的电流模型中相当于物理惯量除以转矩常数，之后还需考虑角度和命令换算 |
| `K` | 普通位置/速度分支中为乘 `s` 的系数，单位 `1/s`；POWER 还用它乘不同幂次的项，需要额外尺度约定 |
| `c` | 普通位置中组合位置误差，速度分支中组合累计速度误差，均应为 `1/s` |
| `c1、c2` | EISMC 中分别乘位置误差和位置误差积分，单位应分别为 `1/s、1/s²` |
| `p、q` | 通过比值构成无量纲指数，必须检查 `p` 非零及比例的适用范围 |
| `beta` | 终端分支中乘带符号的误差幂；指数为 a 时单位应为 `Q^(1−a)/s` |
| `epsilon` | 随分支兼任切换强度、Sat 的除数或幂指数，不能保持统一物理含义，见 B04 |
| `limit` | 控制 Sat 的分段阈值；只有先确定其输入如何归一化，才能明确参数单位和连续性 |
| `u_max` | 输出绝对值上限，与输出同单位 |
| `pos_esp/pos_error_eps` | 位置误差死区，与位置同单位 |
| `vol_error_eps` | 结构中存在速度误差死区字段，但本轮看到的速度计算分支没有使用它 |

B 的推导宣称采用国际标准单位，但 C++ 本身不检查弧度、度或命令单位，不能据此认定实际调用方已遵守该约定。

### 4.3 已发现的问题与需要核对的内容

**B01：初始化不完整。** `Init()` 未覆盖 `p_error_integral、tar_differential_last、tar_differential_second、param_last、smc.u` 等字段；`SetParam()` 又会立即调用依赖旧参数的 `OutContinuation()`。普通局部实例可能读取未初始化内容；全局零初始化也不能替代完整的状态约定。

**B02：死区路径返回零，但 `Out()` 可能仍读到上次输出。** 多个位置分支直接 `return 0`，跳过了第 219 行的 `smc.u=u`。用返回值和用 `Out()` 得到的命令可能不同。这是源码明确可见的接口不一致。

**B03：清状态与改配置混在一起。** `Clear()` 会把配置的误差死区清成零，却不清 `smc.u` 和 `smc.s`，也没有明确重建第一拍历史。复位不能直接照搬。

**B04：饱和函数的两个参数含义耦合。** 它先算 `y=s/epsilon`，再按 `|y|≤limit` 决定返回 `y` 或其符号。`epsilon` 在多个控制分支里同时充当切换项系数，在 POWER 分支里又充当指数。`epsilon=0` 会出现除零；`limit` 不等于 1 时，分段连接也不一定连续。需要重新推导单位、归一化和参数域。

**B05：积分约束未实际启用。** 头文件的积分限制宏没有形成有效的限制逻辑，速度积分限制代码也被注释。输出被限制时，误差累计可能继续增长；后续需要单独研究，而不是声称已有保护。

**B06：参数切换不能保证完整输出连续。** `OutContinuation()` 用 `c2` 是否非零决定是否处理，却在速度累计值的比例中除以 `c`；没有检查相应除数和历史参数。即便这些条件有效，该缩放也只对部分积分贡献成立，不能保证所有参数变化后的总输出都连续。

**B07：存在输入和失败处理缺口。** 未检查非有限数值、非法模式和参数域；`switch` 没有默认分支，非法模式可能使局部 `u` 未赋值。头文件还包含当前参考代码目录中没有提供的 `DebugC.h`。不能把这份源码直接称为独立可编译的生产库。

**B08：原模型里 `tfsmc` 的名称与实际公式不一致。** 只读解包 `simulation/sliding.slx` 后，`stateflow/machine.xml` 把名为 `tfsmc` 的模块映射到 `chart_62.xml`；它实际为 `u=J·(dwd−c·e−epsilon·sign_s−k·s)`。配套 `s1` 映射的 `chart_76.xml` 为 `s=e+c·se`。这与 C++ 终端分支的误差幂公式不同，不能用此模块名称证明终端分支已经被该模型验证。模型也含连续积分、求导模块，不等价于 C++ 的全部差分和调用时序。

## 5. C：复旦 2026，带误差幂与小误差切换的位置控制

### 5.1 实际计算与调用顺序

来源：`smc/SMC/slidingmodec.cpp:7` 的 `SMC_Tick()`。

调用方式：构造实例 → 写入 `target` → 提供角度与角速度 → `SMC_Tick()` → 使用成员 `u`。README 指定角度为度、角速度为度每秒。

为描述源码，定义指数 `a=q/p`，以及带符号的误差幂 `g(e)=|e|^a·sign(e)`。在非零误差处，代码的主要形式为：

- `s=ė+C·g(e)`。
- `ds=−epsilon·Sat(s)−K·s`。
- `u=J·[目标二次变化量+ds−C·a·ė·g(e)/e]`。
- 当 `|e|<1` 时，改用普通线性位置公式覆盖输出。

“有限时间到零”指在某个有限时刻到达零，并在对应理想条件下保持在那里。“终端滑模”通常通过非线性的面内误差关系研究这种性质。这里只有先按实际公式记录为终端形式，再单独核查 README 所称的“快速终端”与实现的对应关系，不先认定名称成立。

C 的 `q、p` 通过比值控制误差幂，二者比值无量纲；`C` 的单位取决于线性分支还是误差幂分支。`K、epsilon、error_eps、u_max` 分别对应线性趋近项、饱和切换项、位置死区和输出上限。`J` 在输出中充当逆输入增益比例，不能仅凭 README 的“等效转动惯量”名称赋予纯机械惯量单位。

### 5.2 值得参考

- 展示把线性误差项改为带符号误差幂的思路。
- README 有推导，可与代码逐项对照。
- 展示在接近零误差处切回普通公式的工程处理，适合作为后期边界问题实验。

### 5.3 已发现的问题与需要核对的内容

**C01：继承 A 的时间和初始化问题。** 目标差分没有除以实际时间，构造函数没有初始化全部动态状态，死区返回仍跳过 `target_last` 更新。

**C02：误差变化率使用上一拍的目标变化量。** 第 15 行先用旧 `target_dot` 计算 `error_dot`，第 17 行才更新本拍 `target_dot`。目标变化时，与使用本拍一致数据的理论式存在时序差异，不能无说明地混用。

**C03：小误差分支并没有避免先做危险运算。** 第 32 行先计算含 `1/error` 的终端输出，第 34 行之后才用普通公式覆盖。极小误差时仍可能先产生很大的中间值；死区为零且误差正好为零时，还可能先执行零除。后续覆盖不等于从未执行。

**C04：指数与阈值没有参数检查。** `p=0`、不合适的比例、非有限参数等没有被拒绝；阈值 `1` 实际依附于度。换成弧度后不能保持数值不变。

**C05：同一个 C 在两个分支里的理论单位不同。** 线性公式里 C 应为 `1/s`；若误差幂指数为 a，C 应为 `Q^(1−a)/s`。共用数值属于需要明确归一化与换算的工程规则，不是天然具有单位无关性的算法。

**C06：近零切回普通形式后，不能照搬理想终端的全程有限时间结论。** 是否平滑、是否存在输出跳变、实际误差到达什么范围，都要按分段后的真实公式验证。README 的命名和理想推导不自动覆盖这个混合实现。

**C07：同样含硬件头文件，输出映射和失败处理不完整。** 不能作为无硬件依赖的生产接口直接纳入。
