# 算法库建设计划与进度

本页管理可复用 C++ 库的建设。2026-10-29 按用户要求先完成库、再教学；普通位置首版已实现并通过主机、MATLAB 独立核对和 ARM 交叉编译。教学按独立路线推进，个人理解另行确认，进度见[学习路线](学习路线与MATLAB索引.md)。

## 1. 最终交付与首版范围

算法库是只负责根据输入数据计算控制结果的可复用代码；对象模型是描述输入怎样影响运动的模型。两者分别放置，模型不进入生产库。

首版目标：一个经过公式、MATLAB 和主机 C++ 结果核对的普通位置滑模控制器，可被不同电机分别创建实例使用。首版先明确一种普通位置公式，不同时照搬三套有差异的写法。

首版不以“支持所有参考分支”为完成标准。速度控制、误差积分位置控制、其他趋近形式及终端形式，按独立学习和验证结果分批增加；每个新增算法都要有自己的适用模型、参数、单位、来源及检查证据。

同一种算法只保留一份实现。不同电机分别持有实例和项目参数；不同任务自行组合需要的组件，不按电机型号复制算法文件。

## 3. 核心与调用方的边界

HAL 是芯片厂商提供的硬件访问接口；RTOS 是负责任务调度等功能的实时操作系统。核心库不依赖它们，也不访问时钟、通信驱动或具体机器人模式。

| 事项 | 核心库职责 | 调用方/应用职责 |
| --- | --- | --- |
| 数据 | 接收显式输入，检查计算所需的有效性 | 获取目标和测量，判断是否可用于本次控制 |
| 时间 | 使用约定的计算间隔，不自行读硬件计时 | 提供与本次采样对应的间隔并保证调用顺序 |
| 单位 | 文档写清每个量的单位关系，检查数值而非猜测单位 | 选定一致单位，完成度/弧度、电流/力矩/协议命令换算 |
| 方向 | 按明确误差定义和模型输入方向计算 | 校准反馈和执行正方向，提供相应模型系数 |
| 输出限制 | 按调用方提供的范围产生明确的受限结果 | 确定项目限制，执行功率分配、最终设备限制与提交 |
| 状态 | 初始化、复位和失败时有确定行为 | 决定何时启动、停机、切换、重新初始化 |
| 机构与业务 | 不识别某种电机或机器人模式 | 处理角度跨圈、机械边界、掉线及任务状态 |

角度跨圈是数值在一圈边界处跳转的表示问题，例如接近 180° 后变成 −180°。算法公式接收怎样的连续角度或最短路径误差，应由应用先明确；不把某种云台的跨圈规则写进通用核心。

同一实例应串行使用，不承诺多个任务同时修改一个实例。不同实例的状态彼此独立；共享的是公式和只读代码，不共享历史值。

## 4. 先冻结数学规格，再定接口

数学规格是对公式、符号、单位、输入前提和一次计算时序的明确描述。进入实现前，至少回答：

1. 误差采用测量减目标还是目标减测量？与三个参考的符号如何对应？
2. 模型输入到底是力矩、电流还是某种命令单位？输入系数怎样与真实项目对应？
3. 目标角度、目标速度与目标加速度是否由调用方直接提供？若缺少某项，允许的调用含义是什么？
4. 若有差分辅助组件，计算间隔、首次样本、历史更新与复位怎样定义？不能暗中把缺失目标速度设为测量速度。
5. 饱和宽度与切换强度分别是什么？两者使用独立且单位明确的参数，不照搬 B 的复用规则。
6. 输出范围、误差死区是否存在，精确含义是什么？若未确定必要性，不默认搬入参考死区行为。
7. 何时计算本次输出，何时推进累计状态？一次输入只推进一次，不发生隐式重复累计。
8. 原参考与统一公式之间有哪些适配？每项保留来源与理由。

首版已经确定采用显式提供目标及其速度、加速度的核心，不保留目标差分或积分历史；因此普通位置公式不接收一个未参与计算的 dt。调用方仍需管理并验证采样时序。已冻结的符号、单位、参数域和公式见[数学规格](普通位置滑模数学规格.md)，接口见[库接入说明](库接入与验证说明.md)。

核心参数不内置任何机器人的惯量、转矩常数、电机编号、输出方向或限幅值。初步计划以秒作为时间单位；角度和输入单位由项目选定并保持一致，示例可以使用弧度和安培但必须写明是假设。

## 5. 初始化、状态复位与失败

“状态”是算法保留到下一次计算的历史量；“配置”是控制公式使用的参数。复位通常清理或重设状态，而不是偷偷改变已经配置的死区和增益。

按以下顺序建立并验证约定：

- 默认构造后所有成员都有确定值，未成功初始化时不输出貌似有效的控制结果。
- 初始化检查参数范围、除数、输出范围和数值是否有限。非有限数值包括无穷大和非数值结果。
- 初始化和更新先完成必要检查，再提交新配置或状态，避免失败留下半更新结果。
- 复位要清理或明确设置历史、累计量、诊断值和旧输出；明确下一次是否重新建立采样基准。
- 失败通过返回状态明确通知调用方。若采用与 ADRC 一致的“失败不修改输出参数和内部状态”，文档与示例必须阻止调用方误把旧输出当成本次成功结果。
- 应用根据返回状态决定本任务该怎样处置；核心不擅自发零电流、切换控制器或恢复机器人模式。

当前采用布尔返回值：失败保持对象与输出参数。HasResult 表示最近成功诊断仍可读取，不代替本次 Calc 的返回值。Reset、成功初始化/改参数/改限制会清除旧诊断，不改变外部设备输出。

## 7. 验证顺序与证据等级

主机测试是在电脑上实际编译运行 C++；交叉编译是用面向 STM32 所用处理器的工具链生成目标代码。它们证明的事情不同。

| 层次 | 要执行的检查 | 不能据此声称 |
| --- | --- | --- |
| 代码检查 | 阅读公式、单位、状态和分支 | 程序已运行或控制效果良好 |
| 简单公式检查 | 零误差、正负号、线性关系、可手算点、分段边界 | 完整动态系统已稳定 |
| 主机测试 | 真正运行 C++，核对初始化、复位、非法参数、失败与多实例独立 | STM32 已可运行 |
| MATLAB 独立计算 | 同一输入序列下比较公式与 C++，明确数值误差 | 电机模型等于实车 |
| MATLAB 应用实验 | 加入声明的对象、采样、扰动、噪声和限制，逐项实验 | 实机一定有效或优于已有控制器 |
| 交叉编译 | 编译真实生产代码、生成对象或静态库 | 固件已完整链接或板上执行正常 |
| 固件接入 | 具体工程完整链接，确认实例、输入输出映射及调用顺序 | 电气与机械闭环已验证 |
| 上板验证 | 板上真实周期、执行时间、数值和输出路径检查 | 整车所有工况已验证 |
| 整车验证 | 实际机器人任务和扰动下记录效果 | 任意其他机器人也有相同性能 |

先做可以手算的点，再做逐次序列核对，再做对象实验。测试只覆盖有意义的数值、状态和边界，不为文档或文件移动编写机械性测试。

比较已有控制器时必须使用一致的目标、对象、采样、测量、限制和指标，并保留整定条件；不预设滑模控制更好。响应时间、误差、输出峰值与波动等指标，到对应实验先定义再使用。
