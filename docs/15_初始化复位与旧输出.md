# 第 15 讲：第一次运行、暂停后重新开始，该保留什么

前置内容：[计算间隔与差分](04_计算间隔与差分.md)、[原参考代码与公式逐句对照](14_原参考代码与公式逐句对照.md)。本讲只研究一次次调用之间保留的数据，不推进实际电机运动。

## 1. 先分清初始化、状态与配置

**初始化是为首次使用设置确定的数据和使用条件。** 一个对象已经被创建，并不等于它内部每个将被读取的数都有合适初值，也不等于控制器已经可以计算。

**状态是保留到后续调用、会影响后续行为的数据。** 例如上一拍目标、上次目标差和上次输出。**配置是规定怎样计算的参数**，例如模型输入系数、控制系数和输出范围。

**复位是按接口约定清理或重设状态，使之后的使用从明确条件开始。** 它是否保留参数、是否修改输出、下一拍是否需要建立历史，都要看实际定义，不能只凭 Reset 或 Clear 这个名字猜测。

本讲还要区分三个位置的数据：

- 控制器内部的历史量，例如原参考的 refl、dref。
- 控制器内部的最近一次计算信息，称为**诊断结果**，例如 s、请求输出和受限输出。
- **调用方命令变量**，即调用控制器的程序用来接收或保存结果的变量，它位于控制器之外。

这些数据不一定由同一个函数清理。更改变量也不等于已经向设备发送新命令；本讲只观察程序里的数值，没有设备提交动作。

## 2. 原参考为什么不能只看构造函数的参数

构造函数是创建 C++ 对象时执行的初始化函数。原参考 A 的 [slidingmodec.h](../SMC_Controller/SMC/slidingmodec.h) 第 21～22 行设置了 C、K、ref 等参数，但没有显式设置 dref、ddref、refl 和 u 等成员。

**静态存储对象是具有程序运行期存储的对象。** 它在这里先得到零初始化，再执行构造函数。原示例的全局 YawSMC 以及本讲专门建立的四个静态对象，都满足这一前提。规则见 [C++ 标准草案的静态初始化说明](https://eel.is/c++draft/basic.start.static)。

普通局部实例不能仅凭使用同一个构造函数，就假定这些遗漏成员也都是零。本讲不执行依赖未设置数值的读取，也不通过“某次恰好读到零”验证它可靠。

即使历史量确定为零，也要继续检查：**零是不是本次目标所需要的历史？**

## 3. 非零静止目标的第一拍

沿用第 14 讲的教学数值：C=.5、K=1、epsilon=2、括号外乘法系数 J_code=.2、Sat 数值阈值 1；本讲位置误差死区阈值 error_eps=.1，输出数值范围 ±1000。

角度输入仍用度，角速度用度每秒。原参考的目标差仍没有时间换算，因此下面原输出只称为数字，不赋予安培单位。

目标从第一次调用起就固定为 5°，测量角度固定为 6°、角速度为零。原对象的 refl、dref 从零开始：

| 调用次序 | 调用前 refl | 本次 dref | 本次 ddref | 原输出数字 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 5 | 5 | 2.8 |
| 2 | 5 | 0 | −5 | −1.3 |
| 3 | 5 | 0 | 0 | −.3 |

第一拍的目标明明是静止的，代码却用“5 减保存的 0”算出目标差 5；第二拍又把旧目标差 5 从零中减掉。前三拍输入相同，输出却因为历史不同而改变。

这是零历史与非零初始目标的关系，没有证明某台机器人的真实启动运动，也没有把原代码的单位问题修掉。若采用目标差分，就需要明确怎样建立首次历史；若已知目标静止并直接提供其速度和加速度，则不必凭零目标历史猜测它们。

## 4. 进入死区，哪些历史更新了

**位置误差死区是对一段小位置误差作特殊处理的规则。** 原参考 A 在 `|angle−ref|<error_eps` 时，将 u 设为零并立即结束本次函数；绝对值 |x| 表示不带正负的大小。

但 [SMC_Tick](../SMC_Controller/SMC/slidingmodec.cpp) 第 12～13 行的 ddref、dref 在判断死区之前已更新，第 29 行的 refl 却在判断之后，提前结束时不会执行。因此不是全部历史一起保持，也不是全部历史一起推进。

用四次输入观察：

| 次序 | 目标 ref / ° | 测量角度 / ° | 是否提前结束 | 本次 dref | 本次 ddref | 调用后 refl | 原输出数字 |
| ---: | ---: | ---: | --- | ---: | ---: | ---: | ---: |
| 1 | 0 | 1 | 否 | 0 | 0 | 0 | −.3 |
| 2 | 1 | 1 | 是 | 1 | 1 | 0 | 0 |
| 3 | 2 | 2 | 是 | 2 | 1 | 0 | 0 |
| 4 | 3 | 4 | 否 | 3 | 1 | 3 | 1.4 |

角速度均为零。第四次调用的相邻目标只从 2° 增到 3°，但 dref 使用仍停在 0 的 refl，算出 3。即使中间两次输出都是零，历史也没有回到一个一致的相邻采样关系。

上表历史列来自 MATLAB 按实际源码顺序重建；原 C++ 真实回放记录输入和公开输出，未通过修改 private 成员去读取或补写历史。

再看一个独立状态：目标角度和测量角度均为零，实际角速度为 +3°/s。原参考只检查位置误差，因此直接输出零；它没有检查此刻仍在运动。位置暂时匹配不等于静止。本讲只记录该分支行为，不为具体机器人制定新的死区策略。

## 5. 不再调用，旧输出会怎样

假设原参考先在目标 0°、测量 1°、角速度零时算得 u=−.3。之后两次观察期间，把目标改为 5°，但没有调用 SMC_Tick：

```text
首次计算：         u = -.3
第一次暂停调用：   u = -.3
第二次暂停调用：   u = -.3
恢复后的第一次：   u = 2.8
恢复后的第二次：   u = -1.3
恢复后的第三次：   u = -.3
```

**暂停调用只表示这段程序没有执行，不会自动给旧输出赋零。** 恢复时仍会从保存的 refl=0、dref=0 处理新的非零目标，所以再次出现前面手算的历史影响。

这些观察事件不代表实际设备收到旧命令或新命令。调用方是否继续提交旧数、是否另外写入停止命令，是控制器外部的行为，本实验没有执行它们。

## 6. 当前库的 Reset 实际清理什么

当前生产库 `SMC::Position` 根据本次显式输入的目标角度、目标角速度、目标角加速度和测量数据计算，不保存目标差分历史。因此没有原参考那组 refl、dref、ddref 需要重建。

Init 是初始化接口；成功后保存参数和输出范围，但尚未产生一次计算结果。Calc 是计算接口；成功后写入调用方命令变量并保存诊断。Reset 是复位接口；成功后保留参数、输出范围和已初始化状态，清除诊断。

**HasResult 是表示内部诊断是否仍有效的标志。** Reset 后它为 false，即使诊断数字被清成零，也不能把这个零当作一次成功计算或已执行的设备命令。平时还须检查本次 Calc 的返回值，HasResult 不能替代它。

本讲使用单位一致的教学参数：b=5°/(s²·A)、c=.5 /s、K=1 /s、epsilon=2°/s²、phi=1°/s，输出范围 ±1000 A；此范围只为避免教学计算被限制，不是设备参数。目标 5°、测量 6°、双方速度与目标加速度均为零时，当前库每次计算为 −.3 A。

| 观察事件 | 调用方命令变量 / A | 内部诊断输出数字 / A | HasResult |
| --- | ---: | ---: | --- |
| 默认对象，只观察 | 17 | 0 | false |
| Init 成功 | 17 | 0 | false |
| 第一次 Calc 成功 | −.3 | −.3 | true |
| 相同输入再次 Calc | −.3 | −.3 | true |
| Reset 成功 | −.3 | 0 | false |
| 调用方自己将命令变量赋零 | 0 | 0 | false |
| 相同输入重新 Calc | −.3 | −.3 | true |

17 是调用方特意写入的观察标记，没有发送给设备。重点在于 Reset 不接收该变量，也不会改写它。将变量赋零与 Reset 是两个分别发生的动作，本实验不把这个赋零示例当作所有工程的停机策略。

另一次 Calc 输入角度误差为零、角速度误差为 +3°/s，当前库计算为 −1.3 A，而非原参考死区分支的数字零。它来自现有公式继续使用速度误差，本讲没有修改生产公式，也没有验证实际制动运动。

本节说明当前已实现接口的行为，不全面展开非法输入、失败保留、多实例使用等主题；它们留到第 20 讲。
