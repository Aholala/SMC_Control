# 库接入与验证说明

首版是普通位置滑模：根据当前位置和速度误差计算控制输出。核心只有 [ALG_SMC.hpp](../main/ALG_SMC.hpp)、[ALG_SMC.cpp](../main/ALG_SMC.cpp)，命名空间 `SMC`，C++11。

不依赖 STM32 硬件接口、任务系统、系统时钟、通信或具体机器人模式。每个电机创建自己的 `SMC::Position` 实例，同一实例串行使用；不同电机共用一份实现，参数分别配置。

## 1. 最小使用

可直接编译运行的完整例子见 [position_example.cpp](../examples/position_example.cpp)。例子中的系数全部是教学假设，不能复制为实机参数。

```cpp
#include "ALG_SMC.hpp"

SMC::Position axis;
SMC::PositionConfig config; // 以下字段由项目填写，默认全零不能初始化。
config.input_gain = project_b;
config.surface_gain = project_c;
config.reaching_gain = project_k;
config.switching_gain = project_epsilon;
config.boundary_width = project_phi;
bool ready = axis.Init(config, project_min, project_max);

// 每个控制时刻：先准备同一时刻的目标和测量，角度表示/方向已统一。
SMC::PositionInput in;
in.target = desired_angle;
in.target_rate = desired_rate;
in.target_acceleration = desired_acceleration;
in.measurement = measured_angle;
in.measurement_rate = measured_rate;
float command = 0;
if (ready && axis.Calc(in, command)) {
    // 使用项目在此提交本次结果，并进行必要的最终限制/命令单位转换。
} else {
    // 使用项目在此执行既有失败策略；不要继续发送旧 command。
}
```

上面 `project_*` 和测量变量是接入位置示意，不是额外库接口。Init 的输出范围须由调用方明确提供，支持不对称范围和 `[0,0]`。

目标速度、目标加速度不会从输入历史推测。设成零即表示调用方采用零变化率；若目标确实在运动，需要提供对应变化率，或明确接受不同于完整运动目标公式的行为。

生产代码不使用时间积分或差分，因此没有 dt 参数。它不会替调用方决定运行周期；周期和延迟仍须在消费项目验证。参数单位、方向、数学模型与具体公式见[数学规格](普通位置滑模数学规格.md)。

## 2. 生命周期与失败约定

| 接口 | 含义 |
| --- | --- |
| `Init(config,min,max)` | 完整检查后提交配置、范围，并清除旧诊断 |
| `SetParameters(config)` | 已初始化后改参数，保留范围并清除旧诊断 |
| `SetLimits(min,max)` | 已初始化后改范围，保留参数并清除旧诊断 |
| `Reset()` | 保留配置和限制，清除旧诊断；无历史差分或积分需要重新建立 |
| `Calc(input,command)` | 成功返回 true 并提交本次结果；失败返回 false，输出参数与对象均保持不变 |
| `GetResult()` | 读取最近成功的误差、误差变化率、滑模变量、请求、受限输出与限幅标志 |
| `HasResult()` | 诊断是否有效；不能替代检查本次 Calc 的返回值 |

未初始化时 Calc、Reset 和改参/改限制均失败。失败初始化不破坏已有有效对象。成功改参不承诺输出连续，调用项目负责处理控制切换。

Reset 使诊断里的数值清零，并不表示已经给设备发送零输入，也不表示零一定在配置输出范围内。只有成功 Calc 才产生可提交的新控制结果。

## 3. 编译与重复运行

固件只需加入 `main/` 头文件路径并编译 `main/ALG_SMC.cpp`。若使用本项目 CMake，目标为 `smc`，固件侧设置 `BUILD_TESTING=OFF、SMC_BUILD_EXAMPLES=OFF`。不编译三个参考目录、examples、MATLAB 和 tests。

生产实现必须保留正常浮点语义，不能用 fast-math。当前 CMake/ARM 脚本显式设置 `-fno-fast-math、-ffp-contract=off、-fno-exceptions、-fno-rtti`；源码在 GNU/Clang 检出 fast-math 时拒绝编译。

PowerShell 7 中执行：

```powershell
& .\tests\verify_host.ps1
& .\tests\verify_arm.ps1
```

脚本从 PATH 查找工具，允许通过 `-Compiler` 指定编译器。主机脚本使用 CMake 的 `--fresh`，需要 CMake 3.24 或更新版本；CMake 工程本身要求 3.16。本机使用 CMake 3.28.1。主机验证还需 Ninja。

MATLAB 库验证直接运行 [run_checks.m](../matlab/验证/run_checks.m)，或在根目录 `start.m` 设置 `mode='验证'`。根目录现在默认教学第 1 讲，不会自动做库验收。库验证依赖 MATLAB、PowerShell 7、主机编译工具；不需要 Simulink 或 MEX。

独立应用入口见 [run_case.m](../matlab/应用方案/01_位置控制/run_case.m)。先完成一次库构建与验证，再运行应用；scenario 选择 1～5。应用只运行所选案例，不自动重跑课程或全部检查。

## 4. 实验参数和预期现象

所有对象参数是教学假设：模型 `角加速度=b×输入+d`，输入立即执行；时间间隔 .001 s，时长 8 s；初始角度 −.2 rad、初始速度 0。

| 参数 | 数值与单位 | 含义 |
| --- | --- | --- |
| b | 3 rad/(s²·A)，反向案例为 −3 | 输入到角加速度的系数，不是物理惯量 |
| c | 4 /s | 位置误差与变化率的组合系数 |
| k | 6 /s | 乘滑模变量的趋近系数 |
| epsilon | 2 rad/s² | 饱和切换项强度 |
| phi | .25 rad/s | 对滑模变量归一化的正宽度 |
| 输出限制 | ±4 A；噪声案例 ±1 A | 由示例提供，不是生产库默认值 |

| 案例 | 主题和预期观察 |
| --- | --- |
| 1 静止目标 | 目标 .5 rad，开始输出受限，随后误差下降；观察请求与最终输出的差别 |
| 2 运动目标 | 目标为两项正弦/余弦组合，显式提供解析速度和加速度，核对运动目标公式 |
| 3 持续外力 | 第 2 s 起加 .4 rad/s² 恒定扰动，面附近应保留小误差；与理论平衡误差核对 |
| 4 反向输入增益 | b 改成 −3，控制输出反向，但声明的对象和控制系数一致，仍能跟踪 |
| 5 测量噪声与限制 | 运动目标，位置测量叠加 .001·sin(71t) rad，速度叠加 .01·cos(53t) rad/s，输出限 ±1 A |

案例 2/5 的目标为 `.25*sin(.8*t)+.15*cos(.45*t)` rad；目标速度与加速度由解析式给出。噪声用确定性波形以便复现，不代表真实噪声统计特性。模型没有摩擦、驱动器响应、通信延迟或结构弹性，不能当作真实电机。

## 5. 本次实际证据

2026-10-29，C++11 主机测试 5/5 通过，其中独立 double 网格检查 540 组；测试包含手算点、参数域、非有限输入、中间量溢出、复位、失败保留、单位换算、不对称限制与实例独立。

MATLAB R2025b 已实际运行：4102 个公式点独立核对、5 个各 8000 次计算的完整闭环。公式点的请求输出最大绝对差约 `2.81e-6`，小于约定的 `1e-5+3e-6×参考绝对值`。闭环比较逐次数据，允许 `2e-5+2e-5×参考绝对值`。

| 案例 | 末次真实位置误差绝对值 / rad | C++ 与 MATLAB 全部列最大绝对差 |
| --- | ---: | ---: |
| 静止目标 | 9.65e-9 | 9.54e-7 |
| 运动目标 | 1.14e-6 | 5.59e-7 |
| 持续外力 | 7.14e-3 | 1.29e-6 |
| 反向输入增益 | 9.65e-9 | 9.54e-7 |
| 测量噪声与输出限制 | 5.54e-5 | 5.58e-7 |

末值是本实验结果，不是实机精度声明。持续外力案例还核对了约 .007142857 rad 的理论平衡误差。

使用 ARM GNU 13.3.1，实际生成 Cortex-M4/FPv4 与 Cortex-M7/FPv5 的 hard-float 静态库；不包含测试或对象模型。没有完整固件链接，没有板上执行、真实 CAN、电机或整车验证。

报告与数据：`build/host/host_verification.json`、`build/arm/verification.json`、`build/验证/验证报告.json`；报告记录生产源码 SHA256。图片和 FIG、原始 CSV、MAT 数据分别保留在对应输出目录。每次运行先将报告标记为未通过，成功后才写通过结果。
