# 第 14 讲：原参考 A 的代码是否与公式相同

前置内容：[计算间隔与差分](04_计算间隔与差分.md)、[从运动关系推导控制输入](09_从运动关系推导控制输入.md)、[抖振与零附近的连续处理](12_抖振与零附近的连续处理.md)、[输出限幅怎样改变趋近关系](13_输出限幅怎样改变趋近关系.md)。本讲只对照原参考 A，不修改它，也不添加新控制器。

## 1. 先定义怎样叫“相同”

**公式与代码一致，是指它们在相同变量含义、单位、输入时刻和执行条件下，计算同一个关系。** 字母相似或代码能运行，不足以说明它与推导等价。

本讲分别做两件事：

- **原写法复现**：保留原表达式和计算顺序，检查它实际算出的数字。
- **统一单位后的计算**：明确每个量的单位，按已知对象关系算控制电流。它是独立的教学对照，不冒充未改动的原代码。

原参考 A 位于 `SMC_Controller/`。本次重新查看了两页[推导附件](../SMC_Controller/附件/滑模控制器设计.pdf)、[实现文件](../SMC_Controller/SMC/slidingmodec.cpp)、[头文件](../SMC_Controller/SMC/slidingmodec.h)及 [README](../SMC_Controller/readme.md)。README 指定输入角度用度、角速度用度每秒；本讲统一计算也选用度，避免暗中把原阈值换成弧度。

## 2. 先把变量对上

| 原名字 | 代码中的实际用途 | 统一公式中的对应 |
| --- | --- | --- |
| angle、angle_now | 当前角度 | θ，单位 ° |
| ang_vel、angle_vel | 当前角速度 | θ̇，单位 °/s |
| ref | 当前目标角度 | r，单位 ° |
| refl | 以前保存的目标角度 | 通常希望是上一拍 r，单位 ° |
| dref | 相邻目标角度之差 | 不是已经换算好的 ṙ |
| ddref | 本次目标差减去先前保存的目标差 | 不是已经换算好的 r̈ |
| error | angle−ref | e=θ−r，单位 ° |
| C | 乘位置误差的系数 | c，单位 1/s |
| K | 乘滑模变量的系数 | K，单位 1/s |
| epsilon | 乘 Sat 返回值的系数 | 统一关系中的 ε，单位 °/s² |
| J | 乘在整个输出括号外的系数 | 需从模型确定，不能只按名字判断 |
| u | 算出的输出数字 | 原工程到安培的换算仍需确认 |

一个点表示随时间的一次变化率，两个点表示再次求变化率；ṙ、r̈ 分别为目标角速度、目标角加速度。**一拍是一次控制计算。历史量是保留到下一拍使用的数。**

## 3. 按实际执行顺序读 SMC_Tick

下面行号对应当前 [slidingmodec.cpp](../SMC_Controller/SMC/slidingmodec.cpp)。

| 行号 | 实际语句 | 当前能判断的含义 |
| --- | --- | --- |
| 9～11 | 保存 angle、ang_vel；error=angle−ref | 与 e=测量减目标一致 |
| 12 | ddref=(ref−refl)−dref | 先使用旧 dref，再计算本次二阶目标差 |
| 13 | dref=ref−refl | 保存本次角度差；没有除以计算间隔 |
| 15～19 | 若 fabs(error)<error_eps，则 u=0 并 return | 小位置误差提前结束，后续语句都不执行 |
| 21 | s=C×error+(ang_vel−dref) | 结构像 s=ce+ė，但相减的两个量需先核对单位 |
| 22 | u=J×[ddref−C×(ang_vel−dref)−epsilon×Sat(s)−K×s] | 输出括号的结构可对照第 9 讲；系数和目标差分尚不一致 |
| 24～27 | 将 u 限制在 ±u_max | 对应第 13 讲的最终输出限幅 |
| 29 | refl=ref | 保存目标历史；提前 return 时不会执行 |

fabs(x) 返回 x 的绝对值；return 在这里表示立即结束本次函数。**位置误差死区是把一段小位置误差作特殊处理的规则**，此处定义为 |error|<error_eps。它和第 12 讲的连续过渡区域不同，也和最终输出限幅不同。

本讲只标出提前返回会改变哪些语句的执行。初始化、死区返回后历史怎样演变，留到第 15 讲单独实验；不把这些问题悄悄改掉后再说是在运行原实现。

## 4. 附件中的 J 与代码中的 J

附件第一页写的是 `θ̈=J×u`，其中 θ̈ 是实际角加速度，u 被描述为电流；第二页由此推导出输出为括号量除以 J。

为避免同名混淆，把对象输入系数统一叫 b：

```text
θ̈ = b × u
u = [r̈ - c × ė - K × s - ε × sat(s/φ)] / b
```

ė=θ̇−ṙ 是误差变化率；s=ė+ce 是滑模变量。sat(x) 在 −1≤x≤1 时返回 x，外部返回相应的 ±1；φ>0 与 s 同单位，用来明确连续处理的阈值。

如果要用原代码“系数乘括号”的结构表达同一个对象，必须有：

```text
代码中的乘法系数 J_code = 1/b
```

b 的单位为 °/(s²·A)，1/b 的单位为 A·s²/°；两者不同。**倒数是 1 除以原数**，例如 5 的倒数是 .2。附件与代码不能同时把同一个数字 5 当成这两个系数。

教学例子：b=5，括号计算为 −1.5°/s²，正确电流为 −1.5/5=−.3 A。使用 J_code=.2 乘括号得到相同结果；若直接把 b 的数值 5 填到乘法位置，会算出 −7.5 这个错误数字，代回对象也不会得到所要求的加速度。

**物理转动惯量是描述物体转动时难以改变角速度程度的机械量。** 电流到角加速度的系数还与电机产生力矩的比例、方向和单位有关。因此本讲依据对象关系判断 b，不因附件把字母 J 称为惯量，就把它与物理转动惯量当成同一个量。

## 5. dref 和 ddref 为什么不能直接当成变化率

**差分用相邻采样值的差来近似变化率。** 计算间隔记为 h，单位 s；下标 k 表示当前拍，k−1、k−2 表示前一拍和再前一拍。

如果每拍间隔相同、此前都执行了 refl 更新，原语句对应：

```text
dref_k  = r_k - r_(k-1)
ddref_k = r_k - 2r_(k-1) + r_(k-2)
```

这两个量的单位仍是角度 °。统一到每秒后应分别为：

```text
目标角速度近似值 = (r_k-r_(k-1)) / h
目标角加速度近似值 = (r_k-2r_(k-1)+r_(k-2)) / h²
```

一个除以 h，另一个除以 h²。不能用同一个比例同时补齐两者。原式中的 `ang_vel−dref` 相当于把 °/s 和 ° 直接相减，量的含义尚未统一；ddref 也不能直接与角加速度项相加。

而且换算后仍是近似值：相邻目标差除以 h 是该区间的平均速度，不一定等于当前瞬时速度。不能再把“差分已除以时间”和“目标变化率完全准确”混成一件事。

原 README 第 46～48 行也明确说其目标差分没有严格统一单位。这是原实现的一项工程处理，本讲不把它直接视作物理公式中的导数。

## 6. 同一个运动目标，用三个间隔核对

采用以下教学假设，全部区别于原工程参数：c=.5 /s、K=1 /s、ε=2°/s²、b=5°/(s²·A)、φ=1°/s；原代码乘法系数设为 .2，死区设为 0、输出数值范围设为 ±1000，保证本实验不经过提前返回且不发生最终限幅。

目标为 `r(t)=t² °`，即在固定单位下，数值等于时间秒数的平方；它的目标角速度是 `2t °/s`、目标角加速度是 `2°/s²`。在同一个 t=1 s 时刻给定 θ=2°、θ̇=2°/s，因此 e=1°。

三个实验的 h 分别为 .01、.1、1 s。每个都先调用 t=1−2h 和 t=1−h 两个时刻来建立相邻目标历史，再在 t=1 对照。前两拍仅用于建立历史，不拿它们的零初始差分当作准确目标变化率；h=1 时第一个时刻是 −1 s，同一个 t² 目标在该时刻也有定义。

最后一拍的期望数值为：

| h / s | 原 dref / ° | 原 ddref / ° | dref/h / (°/s) | ddref/h² / (°/s²) |
| ---: | ---: | ---: | ---: | ---: |
| .01 | .0199 | .0002 | 1.99 | 2 |
| .1 | .19 | .02 | 1.9 | 2 |
| 1 | 1 | 2 | 1 | 2 |

当前准确目标角速度为 2°/s，后向区间平均值为 2−h，所以变化率换算后还留有速度近似误差；这个二次目标的二阶差分则恰好给出准确加速度 2。

分别计算三种输出：

| h / s | 原代码实际输出数字 | 统一单位、使用差分近似的电流 / A | 直接使用准确变化率的电流 / A |
| ---: | ---: | ---: | ---: |
| .01 | 约 −1.09399 | .093 | .1 |
| .1 | 约 −1.039 | .03 | .1 |
| 1 | 约 −.4 | −.4 | .1 |

原输出列只表示原 C++ 实际算出的数字，其混合单位和原工程命令到电流的换算尚未解决，不给它附上安培单位。后两列才使用本讲明确的物理单位。

h=1 s 时，除以 h 和 h² 没有改变数值，所以前两列数值重合；这不证明原写法在任意间隔下都等价。直接提供准确变化率时，当前状态和目标信息都相同，因此三次电流都为 .1 A。

## 7. 怎样实际运行原函数并核对

本讲新增 [reference_a_runner.cpp](../examples/reference_a_runner.cpp)，实际编译并调用未改动的原 `SMC_Tick()`。只在独立目录提供一个包含标准整数类型的同名硬件头文件，满足原头文件对 int8_t 的引用；没有模拟芯片或电流驱动。

**静态存储对象是具有程序运行期存储的对象。** 本次使用三个独立静态对象，构造之前成员先得到零初始化，因此未被原构造函数显式设置的历史量有确定初值。这个前提来自 [C++ 标准草案的静态初始化规则](https://eel.is/c++draft/basic.start.static)，不推广为原类的任意局部实例也自动具有同样初值。完整初始化与复位仍留到第 15 讲。

入口：[run_lesson.m](../matlab/教学/第14讲_原参考代码与公式逐句对照/run_lesson.m)，或根目录 [start.m](../start.m) 设置 `mode='教学'、number=14`。本讲需要 MATLAB、PowerShell 7 的 pwsh 和 g++。入口先调用 [verify_reference_a.ps1](../tests/verify_reference_a.ps1) 编译原文件并输出 3 个案例、9 次真实调用的 CSV，再由 MATLAB 按源码顺序独立重放并逐次比较。

原 C++ 的 float 是用于保存近似小数的数字类型，MATLAB 本实验使用保留更多有效数字的 double。两者比较前固定数值容差为 5×10⁻⁶，不在观察结果后放宽；手算与统一公式的内部比较使用 10⁻¹²。真实编译报告同时保存编译器、参数、源文件摘要及来源未修改记录。
