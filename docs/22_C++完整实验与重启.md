# 第 22 讲：C++ 放入完整实验后的行为与重启

前置内容：[最小普通位置闭环](17_最小普通位置闭环.md)、[初始化失败与多个实例](20_初始化失败与多个实例.md)、[MATLAB 与 C++ 逐次核对](21_MATLAB与C++逐次核对.md)。本讲完成基础主线的最后一个实验，不引入速度控制等后续算法。

## 1. 完整实验多了哪一步

**对象模型是用公式描述被控制物体怎样随输入运动。** **闭环是对象的新状态成为下一次测量，进而影响下一次控制输出的过程。** 第 21 讲只向公式提供准备好的输入；本讲由真实 C++ 库产生电流，再由对象模型推进角度、速度，然后重新测量。

仍采用第 17 讲和既有 verification_runner 的教学对象。θ 为角度 rad，ω 为角速度 rad/s，a 为角加速度 rad/s²，u 为电流 A，b 为每安培引起的角加速度，h 为计算间隔 s：

```text
a = b u_applied
θ_next = θ + ω h + .5 a h²
ω_next = ω + a h
```

一个间隔内把电流和加速度视为恒定，先用同一份旧 θ、ω 计算下一状态；h=.001 s。这里假设电流立即执行，没有摩擦、外力、传感误差、驱动器延迟或通信延迟。θ、ω 用 double 保存，传给库的输入转换为 float。

这些对象和参数只存在主机示例 [position_restart_closed_loop.cpp](../examples/position_restart_closed_loop.cpp)，不写进生产库；不是机器人实测参数。

## 2. 四组实验的条件

四组都从 θ=−.2 rad、ω=0 开始，总时长 8 s。c=4 /s、K=6 /s、ε=2 rad/s²、φ=.25 rad/s；参数和初值沿用既有教学案例。

| 案例 | b / [rad/(s²·A)] | 输出范围 / A | 目标与操作 |
| --- | ---: | --- | --- |
| 1 正向输入增益 | +3 | [−4,4] | 持续运行，目标 .5 rad |
| 2 反向输入增益 | −3 | [−4,4] | 同一目标，对象的 b 与库内 b 同时为 −3 |
| 3 输出受限 | +3 | [−1,1] | 同一目标，观察请求与实际输出 |
| 4 暂停与重启 | +3 | [−4,4] | 1 s 暂停并 Reset；1.5 s 用新目标 −.3 rad 重启 |

案例 2 研究的是输入与对象方向声明匹配时的计算，不是替机器人猜方向。案例 3 只改变明确给出的电流范围；没有增加噪声或外力。

案例 4 的操作时刻是本讲新增的教学假设。目标在重启时直接从 .5 改为 −.3，两个阶段各自采用静止目标的零目标速度与加速度。这个指令切换点不存在有限的连续目标导数；实验检查切换后的调用与数值，不把连续时间的理想推导套到这个瞬间。

## 3. 先手算第一步

案例 1 初始 e=−.2−.5=−.7 rad，误差变化率为零：

```text
s=4×(−.7)=−2.8 rad/s
sat(s/φ)=−1
request=[0−0−6×(−2.8)−2×(−1)]/3=18.8/3 A
output=4 A，limited=true
a=3×4=12 rad/s²
θ_next=−.2+.5×12×.001²=−.199994 rad
ω_next=0+12×.001=.012 rad/s
```

案例 2 的请求和电流符号反过来，但 b 也反过来，因此 b×u 不变，对象运动相同。案例 3 第一步只能输出 1 A，对应 a=3 rad/s²、θ_next=−.1999985 rad、ω_next=.003 rad/s。这些简单关系说明应以最终施加电流推进对象，而不是以原始请求推进。

## 4. 暂停、复位与物理运动分开

**暂停在本示例中被明确规定为：不调用 Calc，并由调用方给对象施加零电流。** **重启是重新允许 Calc，从当前测量和当时目标计算新结果。** Reset 的含义仍是第 20 讲的“清除保存的诊断”，不会让物理角度或速度回到初值。

本例分别记录三个电流量：

| 量 | 含义 |
| --- | --- |
| request | 对象内保存的限幅前请求；HasResult=false 时该诊断无效 |
| caller_command | 调用方变量，暂停或 Reset 本身不会改写它 |
| applied_command | 这个间隔真正用于推进教学对象的电流 |

案例 4 的时间顺序是：

1. t<1 s：正常计算并使用受限输出。
2. t=1 s：调用 Reset，清除诊断；跳过 Calc，施加零电流。
3. 1≤t<1.5 s：继续跳过 Calc；caller_command 保留旧值，但 applied_command 始终为零，HasResult=false。
4. t=1.5 s：使用现有 θ、ω 和新目标 −.3 rad 调用 Calc，结果有效后使用新输出。

由于对象没有摩擦，暂停时 a=0 只意味着速度不再被电流改变；原有速度仍会使角度继续变化。这不是“零电流让所有实物立即停住”的模型。真实设备的停机策略需要在使用项目内定义和验证。

程序保留暂停期间的物理状态，检查重新启动没有把 θ、ω 重置成 [−.2,0]，也没有把旧 caller_command 直接交给对象继续运动。

## 5. 怎样独立检查完整过程

MATLAB 独立闭环函数只接收参数、初值和上述操作时刻，不接收 C++ 的后续控制量或测量。它自己计算每次输入、控制结果与对象运动，再与真实 C++ 全部记录逐次比较。

每一列数值的允许差为 `2×10⁻⁵ + 2×10⁻⁵×|MATLAB参考值|`，在运行前固定，沿用既有闭环检查。每列按自己的单位比较；启用、是否调用、成功、复位事件、结果有效和限幅标志精确比较。发生超差时先记录案例、行和字段，再报错。

还执行另一种检查：从某行的对象 θ、ω 和实际施加电流，按第一节公式重新算下一行 θ、ω。每组 8000 行对应 7999 个可直接比较的相邻状态，总共 31996 组，允许差 10⁻¹²。暂停期间也参加该检查，使用 applied_command，而非旧 caller_command。

CSV 在每次推进对象之前记录状态，因此最后一行为 t=7.999 s。程序用末行的电流再推进一个间隔，另行保存 t=8 s 状态，与 MATLAB 的 8 s 状态比较，没有把两个时刻混用。
