# 第 23 讲：速度误差的累计与速度控制

前置内容：[电机输入与角速度](03_电机输入与角速度.md)、[怎样趋近滑模面](08_怎样趋近滑模面.md)、[从运动关系推导控制输入](09_从运动关系推导控制输入.md)、[C++完整实验与重启](22_C++完整实验与重启.md)。

本讲围绕现有速度库建立理解：先分清速度目标，再解释累计值，最后推导和运行同一条公式。只读取并调用已精简的 `SMC::Velocity`，不新增另一份生产实现，不增加累计限幅等保护策略。

## 1. 先明确现在控制什么

**速度控制是让实际角速度跟随目标角速度。** 位置控制则让实际角度跟随目标角度。

| 任务 | 一个具体目标 | 稳定后希望发生什么 |
| --- | --- | --- |
| 位置控制 | 转到 2 rad | 角度保持在附近，角速度接近零 |
| 速度控制 | 保持 2 rad/s | 继续转动，每过 1 s 约增加 2 rad |

前面位置库使用角速度，是为了知道怎样接近目标角度。本讲的目标本身就是角速度；对象角度仍会运动，但不要求停在某个指定角度。

记实际角速度为 ω，目标角速度为 r，均用 rad/s。**速度误差是实际速度减目标速度**，记为 e：

```text
e = ω - r
```

例如目标 2 rad/s、实际 .5 rad/s，e=−1.5 rad/s，表示速度数值低于目标。这里的 e 已经不是前面的位置误差，不能沿用前面“e 的单位为 rad”的解释。

## 2. 误差累计值是什么

**误差累计值是把每段误差乘以这段时间，再逐段相加得到的状态。** 这种随时间累计的过程也叫积分。本讲记累计值为 z，初始设为零。

先用一个容易算的例子：连续两段速度误差都为 .5 rad/s，每段 .5 s：

```text
第一段贡献 = .5 rad/s × .5 s = .25 rad
第一段结束：z = 0 + .25 = .25 rad
第二段贡献 = .5 rad/s × .5 s = .25 rad
第二段结束：z = .25 + .25 = .5 rad
```

当前误差都为 .5，但累计值不同，因为已经持续的时间不同。如果下一段误差为 −.5 rad/s、仍经过 .5 s，就加上 −.25 rad，z 从 .5 变成 .25 rad。

误差恰好为零时，本段贡献为零，旧累计值保持，不会自动归零。z 的单位虽然是 rad，**它记录的是速度误差的累计，不是对象实际角度 θ**。

连续时间下写成 `z=∫e dt`，上方一点表示时间变化率，因而 `z_dot=e`。实际程序按每次的间隔 h 近似累计：

```text
new_z = old_z + e*h
```

h 即接口中的 dt，单位 s。库不自行读取时间；第一次成功调用也累计一次，重复 Calc 会继续累计。本讲没有累计限幅，也没有在输出受限时冻结累计。

## 3. 本讲怎样组合误差与累计值

**滑模变量是控制设计中用来规定误差关系的组合量**，沿用前面记号 s；使 s=0 的状态集合称为滑模面。本讲采用参考 B 的速度形式：

```text
s = e + c*z
```

c 是正系数，单位 1/s，因此 c×z 与 e 同为 rad/s，s 也用 rad/s。这是本讲选择的速度滑模关系，不表示所有速度控制方法都必须累计误差。

例如 c=2 /s、当前 e=.5 rad/s：

- z=.25 rad 时，s=.5+2×.25=1 rad/s。
- z=.5 rad 时，s=.5+2×.5=1.5 rad/s。

所以当前速度误差相同，并不意味着这两个控制器状态相同。还需要知道累计值。

## 4. 从速度对象推导输入

**求导就是求一个量随时间的变化率。** 使用第 3 讲的理想对象，先忽略外力：

```text
ω_dot = b*u
```

u 为电流 A，b 为每安培引起的角加速度，单位 rad/(s²·A)。目标速度 r 的变化率记为 a_target，即目标角加速度，单位 rad/s²，由调用方提供。

对速度误差和本讲的 s 求变化率：

```text
e_dot = ω_dot - a_target = b*u - a_target
z_dot = e
s_dot = e_dot + c*z_dot = b*u - a_target + c*e
```

沿用第 8、12 讲的规则，让 s 按下面关系趋近零：

```text
s_dot = -K*s - ε*sat(s/φ)
```

K 为乘 s 的系数，单位 1/s；ε 为切换项强度，单位 rad/s²；φ 为零附近连续处理的正宽度，单位 rad/s。sat(x) 在 −1≤x≤1 时等于 x，外部取对应的±1。

把两条 s_dot 联立，再解出 u：

```text
b*u - a_target + c*e = -K*s - ε*sat(s/φ)
u_request = [a_target - c*e - K*s - ε*sat(s/φ)] / b
```

这与位置公式使用的误差关系不同：本讲减去的是 c×速度误差，不是 c×速度误差的变化率。输入不需要实际角加速度测量。

上述关系针对理想连续时间、模型匹配且完整请求能够执行的情形。程序按间隔累计，并可能限制最终输出；不能把理想等式当作任意调用周期下的保证。

## 5. 先算六个连续点

参数沿用现有速度验证的明确点：`[b,c,K,ε,φ]=[2,2,3,4,2]`，输出范围±3 A，初始 z=0。它们只是教学假设。每次先算 e，再把本次 e×h 加入 z，用新 z 算 s 和电流。

输入如下，h 都为 .5 s：

| 次数 | 目标速度 / (rad/s) | 目标加速度 / (rad/s²) | 实际速度 / (rad/s) |
| --- | ---: | ---: | ---: |
| 1 | 0 | 0 | .5 |
| 2 | 0 | 0 | .5 |
| 3 | 0 | 0 | −.5 |
| 4 | 3 | 6 | 3 |
| 5 | 0 | 0 | −1 |
| 6 | 0 | 1 | 1 |

第一点逐项算：

```text
e=.5 rad/s
z=0+.5×.5=.25 rad
s=.5+2×.25=1 rad/s
sat(s/φ)=.5
u_request=(0-2×.5-3×1-4×.5)/2=-3 A
output=-3 A
```

把第一次的 z 留给下一次，可以得到：

| 次数 | e / (rad/s) | 新 z / rad | s / (rad/s) | 请求 / A | 输出 / A |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | .5 | .25 | 1 | −3 | −3 |
| 2 | .5 | .5 | 1.5 | −4.25 | −3 |
| 3 | −.5 | .25 | 0 | .5 | .5 |
| 4 | 0 | .25 | .5 | 1.75 | 1.75 |
| 5 | −1 | −.25 | −1.5 | 4.75 | 3 |
| 6 | 1 | .25 | 1.5 | −4.25 | −3 |

先看第 1、2 次：误差一样，累计和请求不同；最终输出恰好都被限制到−3 A，不能据此说两次计算完全一样。

再看第 3、4 次：s=0 时，当前速度误差仍可非零；当前速度误差为零时，累计也可非零。这与此前“一个组合关系成立，不等于其中每个量都等于零”的区别一致。

六点用于阅读公式与累计顺序，不声称这些人为给定的数据连成了一条物理运动。.5 s 也只为便于手算；下一节用单独的对象实验观察真实数据反馈。

## 6. 一个恒速闭环

闭环是对象的新状态作为下一次测量，影响下一次控制输出的过程。沿用现有速度主机程序的案例1：目标2 rad/s，初始角度和速度均为零，参数 `[3,4,6,2,.25]`，输出±4 A，h=.001 s，总时长8 s，无外力或测量误差。

六点与闭环使用不同参数：前者用于逐项手算，后者沿用既有完整案例，不用两组结果直接比较控制性能。

对象在每个区间用当时的受限电流计算角加速度 a，再推进状态：

```text
a = b*output
θ_next = θ + ω*h + .5*a*h²
ω_next = ω + a*h
```

第一拍以理想小数手算：e=−2，z=−.002，s=−2.008，请求为22.048/3≈7.349333 A；只能执行4 A，因此 a=12 rad/s²。下一时刻角度为.000006 rad，速度为.012 rad/s。

随后每次速度都来自独立对象运动，不再人为填写。图中速度先超过目标，再回到附近，这是这组教学参数的响应。后期速度约为2 rad/s时，角度仍继续增加；不能用位置控制的“转到后停住”来理解这条曲线。

MATLAB 的独立闭环只接收参数、初值和目标，不接收 C++ 后续测量或电流。控制计算使用与库相同的单精度，累计规则一致；对象使用双精度独立推进。单精度、双精度是保留不同数值精度的浮点表示，这里的选择用于核对实际递推，不能把另一种精度的长期累计直接当作逐位相同的结果。
