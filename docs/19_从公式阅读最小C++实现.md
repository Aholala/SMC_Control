# 第 19 讲：怎样把已验证公式对应到最小 C++

前置内容：[从运动关系推导控制输入](09_从运动关系推导控制输入.md)、[初始化复位与旧输出](15_初始化复位与旧输出.md)、[参考B与目标加速度项](18_参考B与目标加速度项.md)。本讲阅读现有生产库并写最小调用程序，不再维护另一份生产算法。

## 1. 先明确两个生产文件各放什么

**头文件是集中列出数据类型和可调用函数的文件**，本库为 [ALG_SMC.hpp](../main/ALG_SMC.hpp)。**实现文件放这些函数实际执行的语句**，本库为 [ALG_SMC.cpp](../main/ALG_SMC.cpp)。

本讲只围绕已经确定的公式：

```text
e = measurement - target
error_rate = measurement_rate - target_rate
s = error_rate + c × e
u_request = [target_acceleration - c × error_rate - K × s - ε × sat(s/φ)] / b
u = max(output_min, min(output_max, u_request))
```

measurement、target 为实际与目标角度，单位 rad；measurement_rate、target_rate 为对应角速度，单位 rad/s；target_acceleration 为目标角加速度，单位 rad/s²。e 是位置误差，error_rate 是误差变化率，s 是滑模变量。

b 为每安培引起的角加速度，单位 rad/(s²·A)；c、K 单位为 1/s；ε 单位为 rad/s²；φ 是零附近连续处理的正阈值，单位 rad/s。sat(x) 在 −1≤x≤1 时返回 x，外部返回相应的 ±1；min、max 分别取较小与较大值。

u_request 是限幅前的电流请求，u 是限幅后的结果，单位均为 A。库没有推进对象运动，因此这一次 Calc 不需要对象运动步长 h。

## 2. 怎样在头文件里找到这些量

**命名空间是一组名字的归属范围**，`SMC::` 表示这个名字属于 SMC。**结构体是把一组相关数据集中起来的数据类型**，其中各个有名字的值称为成员。

当前头文件把参数、输入和结果分别放在三个结构体中：

| 类型 | 保存什么 | 本讲需要看见的成员 |
| --- | --- | --- |
| SMC::PositionConfig | 计算参数 | input_gain、surface_gain、reaching_gain、switching_gain、boundary_width |
| SMC::PositionInput | 本次输入 | target、target_rate、target_acceleration、measurement、measurement_rate |
| SMC::PositionResult | 最近成功计算的信息 | error、error_rate、sliding_variable、requested_output、output、limited |

例如 `config.input_gain` 中的点号表示访问 config 里的 input_gain 成员。参数名字与公式对应为：

| C++ 成员名 | 公式符号 | 本讲教学数值 |
| --- | --- | ---: |
| input_gain | b | 2 |
| surface_gain | c | 2 |
| reaching_gain | K | 3 |
| switching_gain | ε | 4 |
| boundary_width | φ | 2 |

这组参数来自已有 [test_support.hpp](../tests/test_support.hpp) 的 Config；单位采用上一节的 rad、s、A。本讲显式选择输出范围 ±3 A，只为演示正常计算与限幅，不是实机设置，也不用于与上一讲比较性能。

## 3. 先算一个简单点，再读程序

点 A 的目标角度、速度和加速度都是零，测量角度 .5 rad、速度零：

```text
e = .5 rad
error_rate = 0 rad/s
s = 0 + 2×.5 = 1 rad/s
s/φ = 1/2 = .5
sat(s/φ) = .5
c×error_rate = 0 rad/s²
K×s = 3 rad/s²
ε×sat(s/φ) = 2 rad/s²
u_request = (0 - 0 - 3 - 2) / 2 = -2.5 A
u = -2.5 A
```

三个被减去的项与目标加速度同为 rad/s²，合成 −5 rad/s²，再除以 b 才得到安培。请求在 ±3 A 内，因此没有被改变。

## 4. 创建对象并完成一次调用

**类把某类对象需要保存的数据和可以调用的函数组织在一起；对象是按这个类创建的一份具体数据和操作。** `SMC::Position axis` 就创建了一个控制器对象。函数是被调用来完成计算或操作的一段程序；`axis.Init(...)` 表示调用这个对象的初始化函数。

这里只需认识两种数字类型：float 保存近似小数，bool 保存 true 或 false，即真或假。C++ 中 `=` 是把右侧值写入左侧，`0.5f` 的 f 表示使用 float 数字。return 表示结束当前函数并返回一个值。

Init 和 Calc 都返回 bool，本库用 true 表示成功、false 表示失败。`if` 按条件选择执行内容，`!` 表示逻辑取反。因此 `if (!axis.Calc(...)) return 2;` 的含义是计算失败就结束当前主程序并返回非零状态；它没有发送任何设备命令。

**编译器是把 C++ 源码转换成可执行程序的工具。** `#include` 让编译器读入指定头文件；int 保存整数，main 是本次主机程序开始执行的函数。下面程序用 return 0 表示正常结束，非零值表示没有完成对应步骤。

以下短例按文件位于 examples 目录时写头文件路径，包含点 A 的全部输入：

```cpp
#include "../main/ALG_SMC.hpp"

int main()
{
    SMC::PositionConfig config;
    config.input_gain = 2.0f;
    config.surface_gain = 2.0f;
    config.reaching_gain = 3.0f;
    config.switching_gain = 4.0f;
    config.boundary_width = 2.0f;

    SMC::Position axis;
    if (!axis.Init(config, -3.0f, 3.0f)) return 1;

    SMC::PositionInput in;
    in.target = 0.0f;
    in.target_rate = 0.0f;
    in.target_acceleration = 0.0f;
    in.measurement = 0.5f;
    in.measurement_rate = 0.0f;

    float command = 0.0f;
    if (!axis.Calc(in, command)) return 2;
    // 此时 command 应为 -2.5 A。
    return 0;
}
```

短例只完成一次计算。带六点 CSV 输出的可运行程序见 [position_formula_walkthrough.cpp](../examples/position_formula_walkthrough.cpp)，其中不另写控制公式，只调用现有生产库。

## 5. 为什么 Calc 能改写 command

**引用是已有变量或对象的另一个名字**，这里用 `&` 表示。`const` 在这里表示通过这个引用只读 input。引用的这一基本含义可核对 [C++ 标准草案的 References 说明](https://eel.is/c++draft/dcl.ref)。

头文件的接口为：

```cpp
bool Calc(const PositionInput& input, float& command);
```

`float& command` 使函数可以直接写入调用方传来的那个变量，不是只改变一份临时副本。

Calc 根据 input 计算，不通过这个入口改动输入；command 则由成功计算写入。具体的无效输入和失败保留行为留到第 20 讲，本讲仍检查每次返回值。

成功后 `axis.GetResult()` 可读取最近计算的信息。例子用：

```cpp
SMC::PositionResult result = axis.GetResult();
```

把这一刻的诊断结果保存为本地 result，随后读取 result.error、result.sliding_variable 等成员输出到 CSV。本讲的“诊断结果”就是这些供观察计算过程的已保存数值。

## 6. Calc 的计算语句怎样对应公式

下面行号对应第19讲验证时的 [ALG_SMC.cpp](../main/ALG_SMC.cpp)。后续新增速度功能使行号移动，阅读新版应按 Position::Calc 和下列语句内容定位。`next` 是本次计算暂存结果的名字：先算在这里，检查通过后再写入控制器的已保存结果。`-=` 表示从左侧减去右侧，再把结果写回左侧。

| 公式步骤 | 实际语句或变量 | 行号 |
| --- | --- | ---: |
| e=测量−目标 | next.error=input.measurement−input.target | 78 |
| error_rate=实际速度−目标速度 | next.error_rate=input.measurement_rate−input.target_rate | 79 |
| c×e | position_term | 83 |
| s=error_rate+c×e | next.sliding_variable | 84 |
| sat(s/φ) | saturation，按 ±boundary_width 分段 | 88～95 |
| c×error_rate | rate_term | 97 |
| K×s | reaching_term | 98 |
| ε×sat(s/φ) | switching_term | 99 |
| r̈−cė−Ks−εsat | acceleration 先取目标加速度，再依次减三项 | 104～110 |
| 括号量除以 b | next.requested_output | 114 |
| 最终输出限幅 | next.output | 118～122 |
| 是否真的改变请求 | next.limited | 123 |
| 保存结果、改写调用方变量 | result_=next；command=next.output | 125～127 |

中间变量 acceleration 在这里是请求的模型角加速度，不是某个传感器读到的实际加速度；限幅以后，实际交给对象的电流可能变小。

源码把 `sat(s/φ)` 写成先比较 s 与 ±φ，再在内部区域相除，与第 12 讲的同一分段函数对应。它不是把输出电流限制为 ±1 A；真正的电流限制发生在最后。

第19讲验证时的代码逐项检查输入和中间数。后续按用户要求精简为入口状态检查与计算末尾的请求检查，正常数值公式保持一致。下一讲的失败与状态实验仍可检查对外行为。

## 7. 用六个可手算点核对

下面 A～F 对应程序 CSV 的 case_number=1～6。参数与输出范围全部相同：

| 点 | 目标角度 / rad | 目标速度 / (rad/s) | 目标加速度 / (rad/s²) | 测量角度 / rad | 测量速度 / (rad/s) |

| B | 0 | 0 | 0 | 1 | 0 |
| C | 0 | 0 | 0 | −.5 | 0 |
| D | 3 | −4 | 6 | 3 | −4 |
