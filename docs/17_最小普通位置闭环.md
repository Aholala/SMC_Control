# 第 17 讲：最小普通位置控制能否闭合运行

前置内容：[电机输入与角速度](03_电机输入与角速度.md)、[从运动关系推导控制输入](09_从运动关系推导控制输入.md)、[输出限幅怎样改变趋近关系](13_输出限幅怎样改变趋近关系.md)、[运动目标的变化率与数据时刻](16_运动目标的变化率与数据时刻.md)。本讲只运行一个静止目标案例。

## 1. 先定义闭环和本讲的对象

**闭环是把对象运动后的测量结果返回控制器，让它参与下一次控制输出的计算。** 这里的对象是电机转动的简化数学模型，控制器是根据目标与测量计算电流的程序。

**仿真是用数学关系在电脑上计算对象随时间的运动。** 本讲进行闭环仿真：真实生产 C++ 算电流，数学对象用该电流更新角度和角速度，下一次 C++ 再读取更新后的数值。

**反馈是把对象的结果返回控制计算的这条数据路径。** 第 16 讲测量数据提前给定，本讲的下一次测量由本次电流产生的运动决定。

```mermaid
flowchart LR
    R[目标角度与目标变化率] --> C[控制器计算电流]
    C --> U[最终受限电流]
    U --> P[对象运动模型]
    P --> M[更新后的角度与角速度]
    M --> C
```

图中的循环通过一次次相邻时刻的计算实现，不是要求所有数值在同一瞬间互相求解。

## 2. 沿用已有静止目标教学案例

本讲复用 [verification_runner.cpp](../examples/verification_runner.cpp) 的 Config 和 Simulate 中 scenario=1。参数来自现有独立库应用实验，不是实测机器人配置；本次只运行这个案例。

本讲角度使用弧度 rad、时间使用秒 s、电流使用 A；这些数值没有被当作第 16 讲以度为单位那组参数的单位转换。

| 量 | 数值与单位 | 含义 |
| --- | --- | --- |
| b | 3 rad/(s²·A) | 每安培引起的角加速度 |
| c | 4 /s | 将位置误差参与组合的系数 |
| K | 6 /s | 乘滑模变量的系数 |
| ε | 2 rad/s² | 乘饱和函数返回值的切换强度 |
| φ | .25 rad/s | 零附近连续处理的正阈值 |
| 输出范围 | −4～+4 A | 最终电流允许范围 |
| h | .001 s | 两次相邻计算的间隔 |
| 目标 r | .5 rad | 全程不动，目标速度和加速度均为零 |
| 初始角度 θ | −.2 rad | 对象开始的位置 |
| 初始角速度 ω | 0 rad/s | 对象开始时静止 |

本讲假定输入立即执行、每个间隔内电流保持不变，没有额外外力、测量噪声或延迟。角度和角速度都从数学对象直接取得，不使用真实传感器。

## 3. 控制器每次计算什么

位置误差是实际角度减目标角度，记为 e；误差变化率是实际角速度减目标角速度，记为 ė。由于本讲目标静止：

```text
e = θ - .5
ė = ω
s = ė + c × e
```

s 是滑模变量，单位 rad/s。sat(x) 在 −1≤x≤1 时返回 x，在范围外返回相应的 ±1。目标加速度为零时，完整请求电流为：

```text
u_request = [-c × ė - K × s - ε × sat(s/φ)] / b
u = max(-4, min(4, u_request))
```

min 表示取较小值，max 表示取较大值；u 是本间隔实际交给数学对象的受限电流。和第 13 讲一样，请求与执行值分别保留。

核心库只算这一次结果，不负责改变对象角度、等待时间或取得反馈。运动与相邻调用时序由主机实验程序管理。

## 4. 对象怎样把电流变成下一次测量

角加速度 a 是角速度的变化率，单位 rad/s²。本讲对象为：

```text
a = b × u
```

下标 k 表示本次计算前，k+1 表示经过 h 秒后的下次计算前。在这一个间隔内 u 保持不变，因此 a 也保持不变，运动关系为：

```text
θ_(k+1) = θ_k + ω_k × h + .5 × a_k × h²
ω_(k+1) = ω_k + a_k × h
```

第一条的三项分别是原角度、原速度贡献的位移、加速度贡献的位移；第二条是原速度加上这一段的速度变化。两条都使用更新前的 ω_k；不能先改速度，再把新速度放回第一条。

在本节“区间内恒定加速度”的模型下，这两条就是对应的运动关系，不是通过任意挑选间隔就能代表真实电机。

每次循环按下面的顺序发生：

1. 从对象当前状态取得 θ_k 和 ω_k。
2. 准备本时刻目标及其变化率，调用真实 C++ Calc。
3. 记录当前测量、e、ė、s、请求与受限电流。
4. 用受限电流计算 a_k，推进对象到下一时刻。
5. 把新角度和新速度作为下一次反馈，继续计算。

## 5. 先手算第一步

起点 θ=−.2、r=.5、ω=0，因此：

```text
e = -.2 - .5 = -.7 rad
ė = 0 rad/s
s = 0 + 4×(-.7) = -2.8 rad/s
sat(s/φ) = sat(-11.2) = -1
u_request = [0 - 6×(-2.8) - 2×(-1)] / 3
          = 18.8/3 ≈ 6.266667 A
u = 4 A
a = 3×4 = 12 rad/s²
```

经过 .001 s：

```text
θ_next = -.2 + 0×.001 + .5×12×.001² = -.199994 rad
ω_next = 0 + 12×.001 = .012 rad/s
```

这些新值会改变下一次误差和滑模变量。第二次输入中的速度已经不是零，控制器也不应继续把第一次测量当作当前测量。

最初请求超出了限制，因此实际运动不能直接使用“完整请求已执行”的理想趋近关系。本讲按实际受限电流逐步推进，不先假定 s 已经为零或位置误差单调减小。

## 6. 怎样检查闭环确实接起来了

本讲不仅看曲线像不像接近目标，还检查三个具体关系：

- 第一、二次数据与第 5 节手算一致。
- 每个相邻状态，都能由前一个状态与当时真实 C++ 受限输出通过第 4 节的对象关系重建。
- MATLAB 从自己的初值开始，独立算控制电流和自己的对象运动，不读取 C++ 电流或测量去驱动它的对象；最后逐次比较两边的数据。

MATLAB 与 C++ 共用声明的公式、参数和调用顺序，不共用后续状态。这样核对的是两套独立闭环计算，不是把同一份 C++ 轨迹读两遍。

当前 C++ 控制器的 float 是保存近似小数的数字类型，对象状态和 MATLAB 主计算使用保留更多有效数字的 double。MATLAB 在自己的输入进入控制公式前按同样的 float 输入精度取近似值，但公式仍独立计算。

本次沿用已有库闭环验证的逐列数值容差：`2×10⁻⁵ + 2×10⁻⁵×|MATLAB参考数值|`。相邻对象状态重建使用 10⁻¹² 容差。末次记录的位置误差和速度均需小于 2×10⁻⁵（分别以 rad、rad/s 计），这些是本教学案例的检查条件，不是任意机器人性能指标。

本讲记录的对象位置误差 θ−r 与 C++ 诊断中的 error 需区分：后者经过输入数字精度的近似，可能已经显示为零，而对象数值仍留有很小偏差。不能仅凭诊断为零声称数学上或实机上精确到零。
